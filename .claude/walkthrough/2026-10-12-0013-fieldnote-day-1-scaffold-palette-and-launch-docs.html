goal

What the session set out to do

Day 1 of the 30-day UI challenge is a sign-up screen. The product is Fieldnote, a fictional notes and citation workspace for graduate students, faculty and research staff.

Every request was small and concrete: create the project, put it in the right folder, fix a config warning, change colours, then write the documents a real launch would need. Each change to code was verified with npm run lint, format:check, test and build, and every colour change was backed by computed WCAG contrast ratios, not estimates.

Moving the app up a level put reference material (mockups, mood images and, later, a docs/ folder) inside the project's tooling scope. Three side effects had to be fixed.

palette

Switching to Field Journal, then dark mode, then a softer mark

The mood-palettes doc offered nine drop-in palettes. The user picked Field Journal: kraft paper, pine-green ink, apricot marks. Only the hex values changed; every token name stayed, so no component code moved.

The palette doc only defined light values, so dark mode was derived separately (warm brown-black paper, kraft-coloured ink, light pine) and checked pairing by pairing. When asked to "change the contrast of the highlight", the direction was ambiguous, so four measured options were offered. The user chose the softer one.

The trade-off the user accepted

The softer highlighter makes highlighted text easier to read (12.9:1), but the mark itself nearly disappears against the notebook panel (1.02:1), which is where the home page's only highlight sits. The recommended stronger option, EF9A4A, would have kept the mark visible at 1.74:1.

decisions

Choices made along the way

✓ Put the app directly in 01-signup-form/›
A user correction. The scaffold first landed in a nested sign-up-form/ folder; everything was moved up one level after checking for name conflicts, and the build output was dropped since it regenerates.
· Cancel the Claude Design sync›
At the time, src/ held only the starter blue-and-grey Button and no Fieldnote tokens. Syncing would have taught the design agent a generic button. Options were offered (build components first, sync anyway, cancel); the user cancelled. Fieldnote components appeared in the project later in the session.
✓ Map the palette's 14 roles onto the app's tokens›
The palette doc uses spec names (paper-200, moss-50, error-50); the app uses paper-deep, moss-soft and error-soft. The spec names were mapped directly, which matches the spec's own semantic table.
✓ Derive dark mode rather than leave mint-teal›
The old dark moss would not have matched pine. New dark values were proposed, then checked: 18 pairings plus the 92% hover state all passed before anything was written.
+ Soften the highlighter (user overrode the recommendation)›
Recommended: a stronger EF9A4A. Chosen: FBDCB4. Ink on it rises to 12.9:1, but the mark is nearly invisible on the panel. The spec and tokens record it as softened from the palette's value.
✓ Keep brand guidelines in the Fieldnote folder›
Each challenge day is a different product, so the guidelines were saved to 01-signup-form/.claude/ rather than the repo root. All examples use the fictional Northfield University, following the brand's own rule to swap real institution names.
✓ Plan an organic, 12-week campaign›
From the user's answers: drive sign-ups, all three audience segments, 8 to 12 weeks, no budget. The plan builds through the end-of-term crunch and peaks when the spring term starts.
+ Default competitors after the question was skipped›
The user rejected the question and said "resume", so the brief used Zotero, Notion, Obsidian and Mendeley across all focus areas, researched by four parallel agents.
